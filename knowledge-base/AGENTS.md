# 知识库内容开发指南

## 内容模型

- 本目录是知识根目录，可以按主题建立嵌套子目录。
- 除各层开发指南 `AGENTS.md` 外，每个 `.md` 文件是一条完整知识，相对于知识根目录的路径是稳定 sourceName。
- 导入时允许用首行 Markdown heading 作为标题；没有 heading 时使用去掉 `.md` 的文件名。
- `<br>` 会规范化为换行，正文其余结构保持为一整条 content。
- 文件数量会随内容调整而变化；前端和文档不得硬编码当前数量。

## 编写规范

- 面试知识优先使用“中文说明 + 对应英文回答”的成对结构，保证现场能快速阅读并直接使用英文表达。
- 一条知识围绕一个稳定主题，例如自我介绍、客诉 Agent、Monorepo 或贷后催收；主题不同才新增文件。
- 不要为了检索效果把同一主题拆成多个小文件；相关句定位会在完整知识内部完成。
- 英文使用适合口语面试的短句和清晰术语；关键项目名在全库保持一致。
- 指标、时间和个人职责必须有真实依据。占位符用明确方括号保留，不要伪造薪资、日期或通知期。
- 不放入 API Key、账号、客户隐私、未脱敏投诉原文或其他敏感数据。
- 文件会作为完整文本发送给阿里云生成 embedding；写入前确认内容适合该数据流。

## 更新流程

修改或新增 Markdown 后，可在页面“知识库总览”点击“更新知识”，或执行：

```bash
npm run db:ingest
curl http://localhost:8787/api/knowledge/stats
curl http://localhost:8787/api/knowledge
```

- 正常导入应为每个有效文件生成一个完整条目和一个向量。
- 内容哈希未变的文档会直接跳过，不调用 embedding。
- 删除或重命名文件会在下次更新时同步清理数据库中的旧 sourceName。
- 用代表性英文问题调用 `/api/search`，确认能召回目标文件并定位到正确句子。
